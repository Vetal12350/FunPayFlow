# Universal Worker — подготовительный этап, НЕ активирован

Этот документ описывает подготовку одного локального worker к безопасной
работе над несколькими репозиториями. На данном этапе существующий
`scripts/codex_issue_worker.py` **НЕ меняется** и продолжает опрашивать только
`Vetal12350/FunPayFlow`. Новые GitHub Issues для SenReader пока не будут обработаны.

## Профили

В `scripts/worker_projects.py` содержатся два **явно доверенных**
и неизменяемых профиля:

| Проект | Технологии | Допущенные пути | Тестирование |
| --- | --- | --- | --- |
| FunPayFlow | Python + uv | `src/funpayflow/`, `tests/`, `docs/`, `scripts/`, `README.md` | существующие GitHub CI / Product QA |
| SenReader | Flutter/Dart | `lib/`, `test/`, `docs/`, `scripts/`, `README.md`, `pubspec.yaml`, `analysis_options.yaml` | GitHub Actions Android APK |

Репозиторий, remote, branch и разрешённые пути нельзя переопределять
через текст Issue. Новые проекты должны проходить ревью и внесение
в доверенную конфигурацию; автообнаружение открытых репозиториев запрещено.

`allowed_path` — только чистая валидация имени файла: дополнительно
необходимо проверять Git index mode, симлинки, rename, бинарные файлы,
размер diff и глобальные запреты доступа к секретам.

## Порядок последующей интеграции

1. Добавить один scheduler и глобальный lock на всю установку; задачи двух
   репозиториев выполнять последовательно, без конкурирующих workers.
2. Сделать составные ключи `owner/repo#issue` и проверенную атомарную миграцию
   прежнего `state.json` с резервной копией и сохранением всех blocked/started.
3. Параметризовать запросы GitHub, checkout, пути PR и отчёты. Сохранить
   owner+label+prefix проверку. Сохранить запрет shell-команд из текста Issue.
4. Для FunPayFlow сохранить `uv sync --locked --dev` перед запуском Codex.
   Для SenReader не выполнять Flutter-сборки на ПК с токенами: анализ,
   тесты и APK — только в GitHub-hosted Actions.
5. Разделить телеметрию и UI по проектам: heartbeat и PR URLs должны
   проверяться для соответствующего репозитория, а не смешиваться по номеру Issue.
6. Провести regression/security review, полный CI и Windows smoke.
   **Только после явного разрешения владельца** обновить локальную установку
   в состоянии idle, без перезапуска текущей задачи и без второго процесса.

Ни один шаг не разрешает доступ к production VPS, FunPay bot data,
секретам или оплатам. `workspace-write` и удаление env токенов не создают
настоящей изоляции между программами одного Windows-аккаунта.

Связанные задачи: Issue #139 (единый worker), Issue #140 (Control Center UX),
SenReader Issue #2 (интеграция).
