# Локальный Codex Worker

Worker связывает задачи из ChatGPT и GitHub Issues с локальным Codex CLI:
он готовит изменения в отдельном source checkout и создаёт Pull Request (PR).
Работа выполняется на включённом Windows-компьютере владельца.

## Разовая подготовка

Нужны Git, GitHub CLI (`gh`), Codex CLI, `uv` и Python 3.13.
Исходники worker должны находиться в `%LOCALAPPDATA%\FunPayFlowCodexWorker\source`.
В терминале выполните вход в GitHub и Codex:

```text
gh auth login
codex.cmd login
```

Для `gh` используйте GitHub-аккаунт владельца репозитория с правами на PR.
В Codex выберите вход через ChatGPT и авторизуйтесь в браузере
с аккаунтом ChatGPT Plus. Секреты в issue или документацию не вставляйте.

## Проверка и ручной запуск

В **cmd.exe** проверьте доступность инструментов и авторизацию:

```bat
py -3.13 "%LOCALAPPDATA%\FunPayFlowCodexWorker\source\scripts\codex_issue_worker.py" --check
```

`--check` проверяет инструменты и статус входа, но не обрабатывает задачи.
Для ручного запуска выполните в **PowerShell**:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "$env:LOCALAPPDATA\FunPayFlowCodexWorker\source\scripts\start_codex_worker.ps1"
```

Launcher обновляет свой source checkout через `git pull --ff-only`
и запускает опрос очереди каждые 90 секунд. Для остановки нажмите `Ctrl+C`.

## Очередь задач и результат

- Очередь — открытые GitHub issues в `Vetal12350/FunPayFlow` с меткой `codex-local`.
- Принимаются задачи автора `Vetal12350` с заголовком, начинающимся
  с `[Codex] `, и непустым описанием; одной метки недостаточно.
- Задачи выполняются последовательно, по возрастанию номера, каждая
  в отдельном checkout и ветке `codex/issue-<номер>`.
- Локальное состояние предотвращает повторную обработку уже взятых задач,
  включая заблокированные: после ошибки требуется разбор на локальном ПК.
- Доверенный worker публикует ветку и PR, оставляет ссылку в issue и закрывает её.

Изменения проходят через PR, проверку и существующий CI с офлайн-тестами.
Закрытая issue означает создание PR, а не выпуск изменений.
Автоматического merge или попадания в production нет.

## Модель и reasoning effort для каждой issue

Владелец или ChatGPT выбирает профиль один раз при создании разрешённой issue.
В самое начало body, без пустой строки или Markdown-ограждения перед ним, добавьте:

```text
Codex-Model: gpt-6.1-sol
Codex-Effort: medium

Добавить офлайн-регрессионный тест для указанного поведения.
```

Разрешены только `gpt-6.1-sol` и `gpt-6-astra`, effort — только `low`, `medium`,
`high`, `xhigh` (любая из восьми пар). Оба ключа обязательны в показанном порядке,
ровно по одному в первых двух строках; третья строка должна быть пустой, дальше —
непустая задача. Поддерживаются LF и CRLF. Регистр, пробелы и значения точные.
Частичный, повторный или неверный начальный заголовок отклоняется с фиксированным
`Invalid Codex profile metadata` до записи состояния задачи, создания checkout и запуска Codex;
текст ошибки не содержит body. Очередь при этом требует исправления владельцем.
Если начального заголовка нет, старые задачи получают закреплённый
`gpt-6.1-sol` / `medium`. Вхождения ключей внутри обычного описания, включая
заголовок после ведущей пустой строки, остаются текстом задачи и профиль не меняют.
Проверки автора, метки и `[Codex] ` сохраняются; метаданные не дают новых разрешений.

Рекомендуемая политика выбора на стороне ChatGPT:

| Задача | Модель | Effort |
| --- | --- | --- |
| Небольшие docs/tests | `gpt-6.1-sol` | `low` |
| Обычная feature | `gpt-6.1-sol` | `medium` |
| Сложный bug или несколько компонентов | `gpt-6.1-sol` | `high` |
| Ревью безопасности VPS, авторизации, изоляции секретов, deployment/rollback | `gpt-6-astra` | `high` |
| Исключительное архитектурное/security review, только при явном выборе ChatGPT | `gpt-6-astra` | `xhigh` |

Эта таблица не реализована как классификатор: Worker не угадывает профиль по прозе,
не вызывает вторую модель и не принимает произвольные CLI-флаги. Выбор профиля
не разрешает доступ к production или deployment.

Worker передаёт список argv с `shell=False`, сохраняя stdin и ограничения запуска:

```text
codex.cmd --ask-for-approval never exec --sandbox workspace-write --model gpt-6.1-sol -c 'model_reasoning_effort="medium"' --output-last-message <report-path> -
```

Это схема argv, не команда для копирования в cmd.exe: одинарные кавычки лишь
обозначают один аргумент `model_reasoning_effort="medium"` и сами не передаются.
На Windows выбирается npm launcher `codex.cmd`. Согласно
[официальной документации CLI](https://developers.openai.com/codex/cli/reference/),
`exec` поддерживает `--model` и `-c/--config` после подкоманды; approval остаётся перед `exec`.
Совместимая версия CLI должна поддерживать эти флаги и выбранные model/effort.
Числовая минимальная версия здесь не подтверждена, конкретная установленная версия
и доступ аккаунта офлайн-тестами не проверяются. Несовместимый CLI или недоступный
профиль блокирует задачу: фиксированное `Codex model unavailable or CLI failed; no changes pushed`,
без вывода subprocess, повторного запуска с другой моделью или отметки completed.
Timeout остаётся 1200 секунд с очисткой дерева дочернего процесса. Глобальный
`config.toml`, вход в аккаунт и API-ключи не меняются; fallback/принудительного upgrade нет.
Более сильная модель может расходовать больше включённой квоты; доступность зависит
от аккаунта и установленного CLI. Вход через ChatGPT не следует автоматически
считать оплатой API за каждый токен.

Это bootstrapping-изменение: уже запущенный старый Worker не начнёт учитывать
метаданные этой issue. Историческую #89 нельзя прерывать, повторять или менять
задним числом. После PR обязательны Windows/Linux CI, Product/Core QA PASS и
независимое code/security review до merge. После проверенного merge владелец
однократно обновляет локальную копию Worker и перезапускает его **только в idle**,
после завершения текущей задачи. Эта задача не автоматизирует обновление или restart,
не сбрасывает lock/state; перед каждой следующей задачей менять GUI не требуется.

Офлайн-проверка Worker (без реального Codex, сети и секретов):

```text
python -B -c "from pathlib import Path; Path('tests/.offline-tmp').mkdir(exist_ok=True)"
python -B -m pytest -q tests/test_codex_issue_worker.py --basetemp=tests/.offline-tmp/issue-90 -p no:cacheprovider
```

Используйте уже подготовленное окружение с pytest. Артефакты тестов остаются в
`tests/.offline-tmp/`; тесты запускают только mocks и локальные Python/Git проверки.

Worker работает только с исходниками: рабочий бот FunPay, VPS и реальные лоты
не затрагиваются. Он не запускает FunPayFlow и не обращается к реальным
FunPay/Telegram; публикация лотов и deployment в этот процесс не входят.
