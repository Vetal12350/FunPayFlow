# Установка FunPayFlow на VPS

[← FunPayFlow](../README.md) · [Релизы](https://github.com/Vetal12350/FunPayFlow/releases) · [Безопасность](../SECURITY.md)

Эта инструкция рассчитана на человека, который впервые видит VPS, Linux и SSH. Она использует **подготовленный ZIP из GitHub Releases**, обычного пользователя Ubuntu и установщик `linux/install.sh`. Пример команд ниже показывает v1.0.0; для более нового релиза замените номер версии и проверьте его примечания.

## 1. Что такое VPS и нужен ли он

VPS — удалённый виртуальный компьютер в дата-центре. Он может оставаться включённым круглосуточно, даже когда ваш домашний ПК выключен. Это удобно, если нужен бот FunPay 24/7. **VPS не обязателен:** FunPayFlow можно запустить на Windows через `Setup.bat` и `Start.bat`, пока компьютер включён. Мощный игровой сервер и отдельная видеокарта не нужны.

У VPS есть регулярная стоимость и обязанности владельца: обновлять систему, хранить доступ и делать резервные копии.

## 2. Выбор сервера

Для одного небольшого экземпляра можно ориентироваться на **1 vCPU, 1 ГБ RAM, 10–20 ГБ SSD**. Более комфортный ориентир — **1–2 vCPU, 2 ГБ RAM, от 20 ГБ SSD**. Выберите **Ubuntu 24.04 LTS x64** и стабильное подключение к интернету. Это практический ориентир, не измеренный минимум: потребление зависит от нагрузки и включённых функций.

### Примеры VPS-провайдеров

| Провайдер | Что искать в панели | Примечание |
| --- | --- | --- |
| [FirstByte](https://firstbyte.ru/vps-vds/) | VPS/VDS с Ubuntu | Проверьте доступные конфигурации и регион. |

Это примеры, не рейтинг и не спонсоры FunPayFlow. Цены, регионы и конфигурации меняются; проверяйте условия на сайте провайдера перед оплатой. Реферальных ссылок здесь нет.

## 3. Создайте сервер и найдите его IP

В панели провайдера создайте виртуальный сервер с Ubuntu 24.04 LTS x64 и выбранными ресурсами. Сохраните **публичный IP-адрес** из панели и способ входа: пароль или SSH-ключ. В командах ниже `SERVER_IP` — место для **вашего** IP, не готовый адрес. Не публикуйте пароль, приватный SSH-ключ и снимки экрана с доступами.

Если провайдер предложил вход по SSH-ключу, это предпочтительнее для длительного использования. Приватный ключ остаётся только на вашем компьютере.

## 4. Подключитесь из Windows через SSH

Откройте PowerShell и замените `SERVER_IP` адресом из панели:

```powershell
ssh root@SERVER_IP
```

Некоторые провайдеры дают другого начального пользователя вместо `root`; тогда замените имя перед `@`. При первом подключении SSH попросит подтвердить **отпечаток сервера**. Сравните его с данными провайдера, если они доступны, и подтвердите только свой сервер. При вводе SSH-пароля символы могут вообще не появляться — это нормально.

Если соединение не устанавливается, проверьте IP, состояние сервера и правила доступа к SSH в панели провайдера. Если пароль не принимается, проверьте имя пользователя, раскладку и выбранный способ авторизации.

## 5. Подготовьте Ubuntu и обычного пользователя

Следующие команды выполняйте **в SSH-сеансе на сервере**. Обновите пакеты и установите инструменты для скачивания архива:

```bash
sudo apt update
sudo apt upgrade -y
sudo apt install -y curl unzip ca-certificates
```

Если вы вошли как `root`, создайте отдельного пользователя для FunPayFlow:

```bash
adduser funpayflow
usermod -aG sudo funpayflow
su - funpayflow
```

`adduser` попросит придумать пароль. Если вы вошли сразу под другим обычным пользователем с `sudo`, можно использовать его и пропустить создание `funpayflow`. Дальше все команды запускайте **под выбранным обычным пользователем**: `linux/install.sh` отказывается работать от `root`. `sudo` потребуется только при установке службы systemd.

## 6. Скачайте релизный ZIP и проверьте SHA-256

Откройте [страницу релизов](https://github.com/Vetal12350/FunPayFlow/releases) и найдите файлы `FunPayFlow-v1.0.0.zip` и `FunPayFlow-v1.0.0.zip.sha256` в **Assets**. Не используйте автоматически созданный GitHub «Source code (zip)» для обычной установки. Для v1.0.0 команды:

```bash
mkdir -p "$HOME/apps"
cd "$HOME/apps"
curl -fL "https://github.com/Vetal12350/FunPayFlow/releases/download/v1.0.0/FunPayFlow-v1.0.0.zip" -o FunPayFlow-v1.0.0.zip
curl -fL "https://github.com/Vetal12350/FunPayFlow/releases/download/v1.0.0/FunPayFlow-v1.0.0.zip.sha256" -o FunPayFlow-v1.0.0.zip.sha256
sha256sum -c FunPayFlow-v1.0.0.zip.sha256
unzip FunPayFlow-v1.0.0.zip
```

Продолжайте только если `sha256sum` вывел `OK`. Это сравнивает ZIP с опубликованной контрольной суммой; если она не совпадает, удалите скачанные файлы и разберитесь с причиной. При установке более новой версии замените `v1.0.0` **во всех** именах и URL на номер выбранного релиза.

После распаковки пользовательские инструкции и `Setup.bat`/`Start.bat` лежат в корне архива, Python-приложение — в `app/`, Linux-установщик — в `linux/`. Сохраняйте эти папки вместе.

## 7. Установите FunPayFlow

В примере код живёт в `$HOME/apps/FunPayFlow-v1.0.0/app`, а личные данные — отдельно в `$HOME/.local/share/funpayflow`:

```bash
cd "$HOME/apps/FunPayFlow-v1.0.0"
bash linux/install.sh \
  --code-dir "$HOME/apps/FunPayFlow-v1.0.0/app" \
  --data-dir "$HOME/.local/share/funpayflow" \
  --systemd
```

Установщик проверит файлы приложения, создаст отдельный каталог данных с правами `700`, подготовит `uv` и Python 3.13, синхронизирует зависимости из `uv.lock`, затем откроет локальную настройку. `.env` получает права `600`. Если `uv` отсутствует, установщик скачивает официальный скрипт Astral **в файл** и выполняет его; это требует доверия к Astral как поставщику инструмента установки.

При настройке вам понадобятся FunPay Golden Key, токен Telegram-бота, числовые `ADMIN_ID` и `FUNPAY_USER_ID`. Вводите их только в локальном SSH-сеансе. Настройка не проверяет их через FunPay или Telegram; неверные значения обнаружатся при запуске. Повторная настройка предлагает сохранить существующую конфигурацию.

Флаг `--systemd` после успешной настройки создаёт и запускает службу `funpayflow.service`. Без него установщик покажет команду ручного запуска с `FUNPAY_BOT_DATA_DIR`; такой запуск завершится при закрытии сеанса, поэтому для VPS 24/7 удобнее служба. **Существующий unit-файл установщик не перезаписывает.** Если служба уже создана, используйте раздел [обновления](#12-обновление).

## 8. Первый запуск и проверка

Проверьте службу:

```bash
sudo systemctl status funpayflow
```

Статус `active (running)` означает, что процесс запущен, но для проверки работы напишите своему Telegram-боту `/start`. Пройдите мастер настройки модулей и проверьте статус в Telegram. На новой установке десять модулей выбраны по умолчанию; ночной автоответ и запрос отзыва имеют отдельные выключатели. `SAFE_MODE` блокирует автоматические изменяющие действия, даже если автоподнятие включено.

Если бот не отвечает, смотрите журнал службы, а затем проверьте сеть и введённые данные — **не публикуйте их**.

## 9. Управление systemd и логи

```bash
sudo systemctl start funpayflow
sudo systemctl stop funpayflow
sudo systemctl restart funpayflow
sudo systemctl status funpayflow
sudo journalctl -u funpayflow -n 50 --no-pager
sudo journalctl -u funpayflow -f
```

`start` запускает службу, `stop` останавливает, `restart` перезапускает, `status` показывает состояние. `journalctl -n 50` показывает последние строки, `-f` следит за новыми; чтобы выйти из режима `-f`, нажмите **Ctrl+C**. Служба включена для автозапуска после перезагрузки сервера. При аварийном завершении systemd пытается запустить её снова через 10 секунд; это не отменяет необходимости разбираться с причиной.

Дополнительные приватные диагностические файлы находятся в `$HOME/.local/share/funpayflow/logs/`. Журналы могут содержать личные данные: перед передачей кому-либо удалите идентификаторы и секреты.

## 10. Где хранятся данные

**Код** находится в папке распакованного релиза. **Приватные данные** при установке выше лежат в `$HOME/.local/share/funpayflow`: `.env`, `bot_settings.json`, `state.sqlite3` вместе с возможными `-wal`/`-shm`, `bot.lock`, `logs/`, `imports/` и другие файлы состояния. Путь задаётся переменной `FUNPAY_BOT_DATA_DIR`, которую служба получает из своего unit-файла.

Не переносите только одну SQLite-базу отдельно от остальных данных работающего процесса. Если вы запускали проект вручную без `FUNPAY_BOT_DATA_DIR`, данные могли храниться рядом с кодом; автоматического переноса нет. Перед сменой места остановите бот, сохраните полный каталог и только потом переносите его.

## 11. Резервная копия

Остановите службу, чтобы SQLite и настройки не менялись во время копирования:

```bash
sudo systemctl stop funpayflow
umask 077
tar -C "$HOME/.local/share" -czf "$HOME/funpayflow-backup-$(date +%Y%m%d-%H%M%S).tar.gz" funpayflow
sudo systemctl start funpayflow
```

Архив содержит **секреты и пользовательские данные**. Храните его в защищённом месте, проверьте возможность восстановления на отдельной тестовой копии и не прикладывайте к GitHub Issues. Для восстановления остановите службу, сделайте копию текущего каталога, восстановите архив и проверьте права, затем запустите службу.

Если копия делается перед обновлением, пока **не выполняйте** последнюю команду `sudo systemctl start funpayflow`: служба должна оставаться остановленной до установки нового кода и проверки unit-файла.

## 12. Обновление

**Автоматического обновления нет.** Не заменяйте файлы внутри работающего релиза и не копируйте новый код поверх личных данных. Сначала прочитайте примечания к новому релизу: они могут содержать отдельные инструкции миграции. Порядок действий:

1. `sudo systemctl stop funpayflow`; сделайте [резервную копию](#11-резервная-копия) **без запуска службы до окончания обновления**.
2. Скачайте новый подготовленный ZIP и его `.sha256`, проверьте контрольную сумму, распакуйте **в новую папку** рядом со старой.
3. Запустите `bash linux/install.sh --code-dir "<новая_папка>/app" --data-dir "$HOME/.local/share/funpayflow"` **без `--systemd`**. Это синхронизирует зависимости и предложит сохранить текущую конфигурацию. Используйте тот же каталог данных.
4. Если unit по-прежнему указывает на старую папку, обновите его по инструкции соответствующего релиза. Для текущей пакетной структуры `src/funpayflow` команды приведены ниже. Старые опубликованные архивы могут содержать другую внутреннюю структуру; используйте их собственный helper или инструкцию, не смешивайте файлы разных версий.
5. Выполните `sudo systemctl daemon-reload`, `sudo systemctl start funpayflow`, затем проверьте `status`, журнал и Telegram.
6. Сохраните старую папку кода и backup до проверки нового запуска.

Для релиза с пакетной структурой `src/funpayflow` установите `NEW_APP` на **абсолютный путь** к его `app`, затем пересоздайте unit-файл. Выполняйте под тем же обычным пользователем, что и первоначальную установку:

```bash
NEW_APP="$HOME/apps/FunPayFlow-vX.Y.Z/app"  # замените X.Y.Z на установленную версию
"$NEW_APP/.venv/bin/python" -m funpayflow.render_service \
  --code-dir "$NEW_APP" \
  --data-dir "$HOME/.local/share/funpayflow" \
  --output "$HOME/.local/share/funpayflow/funpayflow.service"
sudo install -m 644 "$HOME/.local/share/funpayflow/funpayflow.service" /etc/systemd/system/funpayflow.service
sudo systemctl daemon-reload
sudo systemctl start funpayflow
sudo systemctl status funpayflow
```

Unit хранит пользователя, пути к коду и приватному `.env`. Проверьте их до установки. Новый `linux/install.sh --systemd` сам **не заменит** уже существующий unit.

## 13. Безопасность VPS

Регулярно устанавливайте обновления Ubuntu. Если входите по паролю, используйте длинный уникальный пароль; для постоянного доступа предпочтительны SSH-ключи. Не публикуйте `.env`, `FUNPAY_GOLDEN_KEY`, `BOT_TOKEN`, cookies/session-значения, SQLite, логи, экспорты продаж, резервные копии и приватные SSH-ключи. Обычные проблемы сообщайте в [Issues](https://github.com/Vetal12350/FunPayFlow/issues), уязвимости — приватно по [SECURITY.md](../SECURITY.md).

## 14. Частые ошибки

| Симптом | Что проверить |
| --- | --- |
| SSH: `Connection refused` или timeout | IP из панели, сервер включён, доступ к порту SSH разрешён у провайдера. |
| SSH: `Permission denied` | Имя пользователя, пароль/ключ, раскладку; не отправляйте пароль в Issue. |
| `linux/install.sh` отказывает в запуске | Вы не должны быть `root`; путь к `app` и каталогу данных должен быть абсолютным и разным. Скрипт можно запускать через `bash`, без смены executable bit. |
| Не скачивается ZIP/зависимости | Проверьте сеть, URL и место на диске. `uv` может потребовать доступ к пакетам при первом запуске. |
| `funpayflow.service` не стартует | `sudo systemctl status funpayflow` и `sudo journalctl -u funpayflow -n 50 --no-pager`; проверьте пути unit и права на `.env`. |
| Бот молчит в Telegram | Убедитесь, что процесс запущен, токен и `ADMIN_ID` указаны верно и нет второго экземпляра с тем же токеном. |
| Ошибка FunPay-авторизации | Проверьте локальный Golden Key и `FUNPAY_USER_ID`; не публикуйте их значения. |
| Служба повторно запускается | systemd настроен на `Restart=on-failure`; найдите первичную ошибку в журнале. |
| Данные «пропали» после обновления | Проверьте, что новый unit использует прежний `FUNPAY_BOT_DATA_DIR`; не создавайте вторую пустую папку данных. |

При обращении за помощью укажите версию, ОС и **обезличенное** сообщение об ошибке. Перед публикацией скриншота или журнала удалите токены, ключи, личные ID, данные заказов, IP сервера и пути с вашим именем.

## 15. FAQ

**Будет ли бот работать после закрытия PowerShell?** Да, если вы установили и запустили службу systemd: процесс работает на VPS, а PowerShell нужен только для управления сервером.

**Нужен ли VPS для первого знакомства?** Нет. Начать проще на Windows через `Setup.bat` и `Start.bat`.

**Нужно ли ставить Python вручную?** Установщик использует `uv` и готовит Python 3.13. Если сеть или загрузка инструмента недоступны, сначала устраните эту проблему.

**Можно ли перенести данные в другую папку?** Да, после остановки службы и полной резервной копии. Затем настройте тот же абсолютный `FUNPAY_BOT_DATA_DIR` в новом unit-файле; автоматического переноса нет.
